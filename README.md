# שאלון אפיון עיסוק הדרכתי — קה״ד / קצין צפ״ה

אפליקציית שאלון חד-קובצית (`index.html`) המסווגת משיבים לפרופיל העיסוק המתאים —
**קה״ד** או **קצין צפה** — על בסיס אופן העבודה שלהם בפועל.
אין צורך בשרת, בהתקנה או בהרשמה: פותחים את הקובץ בדפדפן או מארחים אותו כאתר סטטי.

---

## מבנה המערכת

### ממשק המשיב
1. **מסך פרטים** — שם מלא ויחידה, שניהם שדות חובה. אי אפשר להתחיל בלעדיהם.
2. **36 שאלות**, אחת בכל מסך, בנוסח המקורי וללא שינוי, תוספת או גריעה.
   לכל שאלה סולם קבוע:
   `1 – כלל לא` · `2 – במידה מועטה` · `3 – במידה בינונית` · `4 – במידה רבה` · `5 – במידה רבה מאוד`
   * מחוון התקדמות (`שאלה 4 מתוך 36`) ופס התקדמות
   * כפתור **הבא** מושבת עד לבחירת תשובה
   * כפתור **חזרה** מופיע החל מהשאלה השנייה
   * ניווט מקלדת: מקשים `1`–`5` לבחירה, `Enter` למעבר, `Backspace` לחזרה
3. **מסך סיום** — הודעת תודה בלבד. **לא מוצג למשיב שום מידע על התוצאה**:
   לא הסיווג, לא הציונים, לא הפער, לא אחוזי התאמה ולא גרף.
   התוצאה אף אינה מחושבת בזמן מילוי השאלון — נשמרות התשובות הגולמיות בלבד,
   והחישוב מתבצע רק בעת הצגת הנתונים באזור המנהל.

### אזור המנהל
כניסה בכתובת `#admin` (קישור דיסקרטי מופיע במסך הפתיחה בלבד) ומוגנת בסיסמה.
לאחר הכניסה מוצגת טבלת כל המשיבים: שם מלא, יחידה, תאריך מילוי, תוצאה,
ציון קה״ד, ציון קצין צפה, פער ורמת ביטחון.

* **חיפוש לפי שם** ו**חיפוש לפי יחידה**
* **סינון לפי תוצאה**: קה״ד / קצין צפה
* **פירוט משיב** — כרטיס עם הפרטים, תאריך ושעת המילוי, כל 36 התשובות שנבחרו,
  שני הציונים, הפער, התוצאה הסופית ורמת הביטחון
* **ייצוא ל־Excel / CSV** — כולל כל התשובות והסיווגים, מייצא את התצוגה המסוננת
* **גיבוי JSON / ייבוא גיבוי** — לאיחוד נתונים שנאספו בכמה מכשירים

## מנגנון הזיהוי

הסיווג נגזר ישירות משתי הגדרות התפקיד ולא מפרופיל אישיות או מהשערה.
ציר ההבחנה בין שני התפקידים:

| | קה״ד — **ניהול** ההדרכה | קצין צפ״ה — **פיתוח** ההדרכה |
|---|---|---|
| ליבה | תכנון, תיאום וסנכרון | איכות, בקרה ותיקוף |
| ביטויים | תכנית עבודה שנתית, גרף הכשרות, לוזים וגאנט, שעון הדרכה ומעקב תכנון מול ביצוע, ניהול משאבים ועזרי הדרכה, הכנת סגלים, מערך החניכה, ניהול ושימור ידע ואתר היחידה | ביקורות מקצועיות, תיקוף ואישור תכנים ומבחנים, בניית ושיפור תכני הדרכה, יסודות מנצחים, הערכה ותצפיות, כשיר להכשיר, חניכה על חניכה |

לכל אחת מ־36 השאלות הוגדר זוג משקלים `[קה״ד, צפ״ה]` בסולם `0–3`
(`0` ללא זיקה, `1` זיקה משנית, `2` זיקה בינונית, `3` זיקה מובהקת).
המשקלים מרוכזים במערך `WEIGHTS` בקובץ `index.html`, לצד השאלות עצמן.
שאלות המופיעות בשתי הגדרות התפקיד (למשל ניהול ידע או בקרה על עמידה ביעדים)
קיבלו משקל דומה לשני הצדדים ולכן כמעט אינן מכריעות — ההכרעה נשענת על השאלות המבחינות.

**החישוב:** כל תשובה מתורגמת לערך `0–1` (`1→0`, `5→1`), מוכפלת במשקל השאלה לאותו פרופיל,
והסכום מנורמל לפי סכום המשקלים ומוצג בסולם `0–100`.
הנרמול מבטיח שקילות בין שני הפרופילים גם כאשר מספר השאלות הרלוונטיות לכל אחד מהם אינו זהה.

**ההכרעה חד-משמעית תמיד** — קה״ד או קצין צפה, ללא תוצאת ביניים:
נבחר הפרופיל בעל הציון הגבוה יותר, ויהא הפער אשר יהא.

כאשר שני הציונים יוצאים זהים לחלוטין מופעל שובר שוויון מדורג:

1. **השאלות הבלעדיות** — אלה שמשקלן לאחד הפרופילים הוא `0`
   (למשל ביקורות מקצועיות מול ניהול לוזים וגאנט). משווים את ממוצע התשובות בשתי הקבוצות.
2. **השאלות המבחינות ביותר** — אלה שהפרש המשקלים בהן הוא `2` ומעלה.
3. פרופיל אחיד לחלוטין (אותה תשובה בכל 36 השאלות) מוכרע דטרמיניסטית לטובת קה״ד.

כדי שהמנהל ידע עד כמה ההכרעה מובהקת, גודל הפער מדווח כ**רמת ביטחון**:

| פער | רמת ביטחון |
|---|---|
| `20+` | גבוהה |
| `13–19` | בינונית |
| `8–12` | נמוכה |
| `0.05–8` | נמוכה מאוד — פער זניח |
| `0` | נמוכה מאוד — הוכרע בשובר שוויון |

רמת ביטחון נמוכה אינה משנה את התוצאה, אלא מסמנת למנהל שהמשיב עוסק בשני התחומים
במידה דומה וכדאי להשלים את התמונה בשיחה.

## הגדרות

כל ההגדרות מרוכזות באובייקט `CONFIG` בראש ה־`<script>` שבקובץ `index.html`:

| הגדרה | משמעות |
|---|---|
| `adminHash` | תקציר SHA-256 של סיסמת המנהל. **סיסמת ברירת המחדל: `hadracha2026`** |
| `webhookUrl` | כתובת `POST` אופציונלית לשליחת כל משיב לשרת חיצוני. ריק = אחסון מקומי בלבד |
| `lowConfidenceGap` | הפער שמתחתיו ההכרעה מתויגת כרמת ביטחון נמוכה מאוד (ברירת מחדל: `8`). אינו משפיע על התוצאה עצמה |
| `storeKey` | מפתח האחסון המקומי |

### החלפת סיסמת המנהל
מחשבים SHA-256 לסיסמה החדשה ומדביקים את התוצאה בשדה `adminHash`:

```bash
printf '%s' 'הסיסמה-החדשה' | sha256sum
```

## אחסון הנתונים ומגבלותיו

ברירת המחדל היא אחסון מקומי בדפדפן (`localStorage`), ומכאן שתי מגבלות שחשוב להכיר:

1. **הנתונים נשמרים בדפדפן שבו מולא השאלון.** מילוי בכמה מכשירים שונים
   מחייב איסוף באמצעות גיבוי JSON וייבוא, או הגדרת `webhookUrl`.
   לאיסוף ריכוזי אמיתי מומלץ להפנות את `webhookUrl` לנקודת קצה
   (למשל Google Apps Script המזין גיליון Google Sheets).
2. **הגנת הסיסמה היא הגנת ממשק, לא הצפנה.** האפליקציה רצה כולה בצד הלקוח,
   ולכן מי שקורא את קוד המקור יכול לראות את מטריצת המשקלים.
   המשיב אינו רואה את התוצאה בשום שלב בממשק, אך אם נדרשת הפרדה הרמטית
   בין הנתונים למשיב — יש להעביר את השמירה והחישוב לשרת.
